# Подробный разбор кода лабораторной работы № 1

В этой папке лежат учебные копии файлов сайта с поясняющими комментариями. Рабочая версия находится на уровень выше: `../index.html`, `../css/style.css` и `../js/script.js`. Комментарии добавлены только в копии для изучения и не меняют работу страницы.

Структура папки:

```text
Разбор кода/
├── index.html       HTML-копия с пояснениями структуры и атрибутов
├── css/
│   └── style.css    CSS-копия с пояснениями блоков и свойств
├── js/
│   └── script.js    JavaScript-копия с пояснениями функций и событий
└── README.md        Этот разбор
```

Комментарии в HTML-копии ссылаются на картинки из `../assets/images/`, а CSS-копия — на шрифты из `../../assets/fonts/`. Благодаря этому ресурсы не дублируются. Если копию открыть через Live Server, она отображается вместе с картинками и шрифтом. Для сдачи и изменения сайта используйте рабочие файлы уровнем выше.

## 1. Как браузер собирает страницу

Файлы работают вместе, но у каждого своя роль:

1. Браузер читает `index.html` и создаёт элементы: шапку, галерею, карточки, формы.
2. В теге `<link>` браузер находит `css/style.css` и применяет оформление к элементам с соответствующими классами и состояниями.
3. В теге `<script>` подключён `js/script.js`. Скрипт находит элементы по `id`, классам и `data-*`-атрибутам, затем реагирует на клики, ввод и отправку форм.

Например, у кнопки есть `data-open-form="register"`. JavaScript выбирает все кнопки с `data-open-form`, а при клике читает значение `register` и показывает форму регистрации. Класс `text-button` отвечает за внешний вид кнопки в CSS, а `type="button"` не даёт ей случайно отправить форму.

## 2. Разбор HTML

### Начало документа и `<head>`

- `<!DOCTYPE html>` включает современный стандарт HTML5. Это декларация, а не обычный элемент страницы.
- `<html lang="ru">` — корневой элемент. `lang="ru"` указывает язык текста браузеру, поисковику и программе чтения экрана.
- `<head>` содержит настройки и ссылки на ресурсы; они не являются видимой частью страницы.
- `<meta charset="UTF-8">` задаёт кодировку. UTF-8 содержит русские символы, поэтому текст не превращается в нечитаемые знаки.
- `<meta name="viewport" content="width=device-width, initial-scale=1.0">` говорит мобильному браузеру считать шириной страницы ширину устройства (`width=device-width`) и не уменьшать страницу начальным масштабом (`initial-scale=1.0`). Без этой настройки мобильные медиазапросы могут работать не так, как ожидается.
- `<title>` задаёт название вкладки и заголовок страницы в закладках.
- `<link rel="stylesheet" href="css/style.css">` подключает CSS. `rel="stylesheet"` сообщает тип связи, `href` задаёт путь к файлу.
- `<script src="js/script.js" defer></script>` подключает JavaScript. `src` — путь к скрипту. `defer` разрешает браузеру сначала разобрать HTML и только потом выполнить файл. Поэтому скрипту не нужно запускаться раньше, чем появятся кнопки и формы.

### Шапка

`<header class="header container">` обозначает верхнюю часть сайта. `class` может содержать несколько классов через пробел: `header` задаёт правила шапки, `container` задаёт общую ширину и центрирование. Классы связывают HTML с CSS; они сами по себе не меняют поведение.

Внутри находится ссылка-логотип:

- `<a href="index.html">` делает логотип ссылкой на главную страницу. У ссылок используется `href`, у кнопок — события.
- `aria-label="Скриншоты — главная страница"` задаёт доступное имя ссылки. Оно полезно, когда видимая часть ссылки состоит преимущественно из картинки.
- `<img src="assets/images/logo.svg" width="40" height="40" alt="">` показывает SVG. `src` — адрес файла. `width` и `height` сразу резервируют место заданного размера и помогают избежать скачка разметки при загрузке. Пустой `alt` говорит, что это декоративная картинка: рядом есть текст «Скриншоты», повторять его программе чтения экрана не нужно.
- `<span class="logo-text">` оборачивает только название. CSS скрывает этот текст на узком мобильном экране.

`<nav aria-label="Вход и регистрация">` группирует действия навигации. Подпись `aria-label` помогает понять, что именно находится в этой навигационной группе.

У кнопок шапки важны атрибуты:

- `type="button"` означает обычную кнопку. Без него кнопка внутри `<form>` по умолчанию стала бы кнопкой отправки; здесь форма не отправляется.
- `data-open-form="register"` и `data-open-form="login"` — пользовательские data-атрибуты. Они хранят короткое значение для скрипта, не задавая внешний вид.
- `class="text-button"` выбирает стиль кнопки в CSS.

### Основная часть и карточки

`<main class="container">` содержит основное уникальное содержимое страницы. Контейнер совпадает по ширине с шапкой и подвалом.

`<h1>` — главный заголовок страницы. Он важен для структуры документа и читателей с программами чтения экрана. Внешний размер задаётся CSS, а не атрибутом HTML.

Кнопка «Добавить скриншот» размечена как `<button>`, потому что это действие. Атрибуты:

- `type="button"` исключает отправку формы;
- `disabled` отключает её, пока действие не реализовано;
- `aria-label` даёт доступное имя для мобильного варианта, где CSS скрывает видимый текст;
- вложенный `img` показывает значок плюс, `width`/`height` задают его размеры, пустой `alt` означает, что значок декоративный, а назначение уже названо у кнопки.

`<section class="cards" aria-label="Общедоступные скриншоты">` группирует карточки как один раздел галереи. `aria-label` описывает раздел, а `class="cards"` подключает CSS Grid.

Каждый `<article class="card">` — отдельная карточка. `<article>` подходит, потому что карточка является самостоятельной единицей списка. Внутри:

- `<img src="..." alt="...">`: `src` указывает фотографию, `alt` коротко описывает её, если картинка не загрузилась или содержимое читается скринридером. Имена файлов и описания у карточек разные.
- `<time datetime="2022-08-15">` — дата. `datetime` даёт машиночитаемое представление в формате год-месяц-день, а видимый текст внутри элемента предназначен человеку.
- `<span class="date-prefix">` выделяет слова «Добавлено». На телефоне CSS скрывает только этот фрагмент.
- Вложенная иконка часов имеет класс `clock`. Она скрыта на большом экране и показана в мобильном варианте.

У всех 12 карточек одинаковая структура, меняются только файл изображения и его описание. Повторение в HTML здесь проще для начинающего, чем генерация списка через JavaScript: карточки статичны по заданию.

Кнопка «Показать еще» имеет `disabled`, потому что AJAX-загрузка не входит в эту работу. `type="button"` оставлен явно, чтобы элемент не приобрёл поведение отправки формы при возможном переносе разметки.

### Подвал и формы

`<footer class="footer container">` обозначает нижнюю часть страницы. Ссылка `href="mailto:info@gmail.com"` попросит устройство открыть почтовую программу с указанным адресом.

`<dialog id="auth-modal" aria-label="Вход и регистрация">` — встроенное модальное окно HTML. `id` уникален и используется JavaScript для поиска именно этого окна. `aria-label` даёт ему доступное имя. Браузер умеет открыть его поверх страницы и закрыть клавишей Escape.

Кнопка закрытия имеет `type="button"`, потому что она находится рядом с формами и не должна их отправлять. `aria-label="Закрыть окно"` называет кнопку, так как видимое содержимое — только изображение крестика. У изображения `alt=""`, потому что назначение передано самой кнопке.

Переключатели формы — обычные кнопки с `data-switch-form="register"` или `data-switch-form="login"`. HTML хранит идентификатор нужного состояния, JS меняет видимость форм, CSS меняет цвет активной вкладки.

Форма регистрации `<form id="register-form" novalidate>`:

- `id` позволяет JavaScript обратиться к конкретной форме и её полям;
- `novalidate` выключает стандартные всплывающие сообщения браузера. Мы используем встроенные проверки браузера, но показываем текст ошибки прямо под каждым полем;
- отдельные обёртки `<div class="field">` объединяют поле и относящийся к нему текст ошибки. CSS задаёт им место в сетке.

`<label for="register-name">` связывает подпись с полем, чей `id="register-name"`. Щелчок по подписи переводит фокус в поле. Класс `visually-hidden` скрывает подпись только визуально, сохраняя её для скринридера.

Атрибуты `<input>`:

| Атрибут | Для чего он нужен здесь |
| --- | --- |
| `id` | Уникально находит поле и связывает его с `label` через `for`. |
| `name` | Имя значения в `FormData`, например `phone` или `email`. Без `name` поле не попадёт в собранные данные. |
| `type` | Вид поля и базовое поведение браузера: `text`, `email`, `tel`, `password` или `checkbox`. |
| `placeholder` | Короткая подсказка внутри пустого поля. Не заменяет подпись `label`. |
| `autocomplete` | Подсказывает браузеру назначение данных для автозаполнения: имя, email, телефон, новый или текущий пароль. |
| `required` | Обозначает обязательное поле и создаёт состояние `valueMissing`, доступное проверке JS. |
| `minlength="6"` | Минимальная длина пароля. Дополнительное сообщение формирует JS. |
| `aria-describedby` | Ссылается по `id` на `<small>` с ошибкой и связывает текст с полем для вспомогательных технологий. |

`type="email"` позволяет браузеру обнаружить очевидно неправильный адрес. `type="tel"` обозначает номер телефона и на некоторых устройствах открывает удобную клавиатуру, но не проверяет российский номер — это делает JS. `type="password"` визуально скрывает символы. `type="checkbox"` создаёт флажок согласия; `required` запрещает продолжать без отметки.

`<small class="error" id="phone-error"></small>` — заранее созданное место сообщения. Пустой элемент не занимает место из-за правила CSS `.error:empty`. Поле с `aria-describedby="phone-error"` связано с ним.

Ссылка на политику внутри текста согласия имеет `target="_blank"`, чтобы открыть источник в новой вкладке. `rel="noopener noreferrer"` ограничивает связь новой вкладки с текущей страницей и не передаёт ей адрес предыдущей страницы.

`<p class="form-status" role="status">` предназначен для результата успешной отправки. `role="status"` сообщает скринридеру об изменении текста без принудительного переноса фокуса.

Форма входа устроена похоже, но у неё свои `id` и сообщения об ошибках. Атрибут `hidden` скрывает её в начале. JavaScript убирает `hidden`, когда пользователь выбирает вход. Два отдельных `<form>` упрощают работу: можно проверить или собрать данные только выбранной формы.

## 3. Разбор CSS

CSS состоит из правил вида `селектор { свойство: значение; }`. Селектор находит элемент, свойство описывает, что изменить, значение задаёт конкретное оформление. Класс из HTML начинается точкой в CSS (`.card`), `id` — знаком `#` (`#login-form`), тег можно выбрать напрямую (`body`, `h1`), а атрибут — в квадратных скобках (`[hidden]`).

### Шрифт и общие правила

Каждый блок `@font-face` регистрирует один локальный файл Inter. `font-family` задаёт семейство, `src` — путь, `format("woff2")` сообщает формат, `font-weight` связывает файл с толщиной 400, 500 или 600. `font-display: swap` сначала показывает системный шрифт, а после загрузки меняет его на Inter, чтобы текст не пропадал.

`* { box-sizing: border-box; }` применяет удобную модель размеров ко всем элементам: указанная ширина включает padding и границу. Без неё фактическая ширина элемента становилась бы больше заданной.

Правило `body` снимает стандартный внешний отступ браузера, задаёт основной цвет и сокращённо описывает размер/межстрочный интервал/семейство шрифта. `Inter, sans-serif` содержит запасной шрифт на случай, если Inter не загрузится. Правило `button, input { font: inherit; }` заставляет элементы формы наследовать тот же шрифт, что и страница.

`a`, `a:hover`, `button:focus-visible` оформляют ссылки и заметный клавиатурный фокус. `:hover` действует при наведении мыши; `:focus-visible` показывает рамку, когда элемент выбран клавиатурой. `outline-offset` отодвигает контур от края, чтобы его было видно.

Селектор `[hidden]` принудительно скрывает элементы с HTML-атрибутом `hidden`. `!important` нужен из-за того, что некоторые CSS-правила элементов форм или сетки иначе могут переопределить стандартное скрытие.

### Контейнер, шапка и заголовок галереи

`.container` использует ширину `calc(100% - 80px)`: от ширины окна остаётся по 40 пикселей бокового поля. `max-width: 1200px` прекращает рост содержимого на широких мониторах, `margin: 0 auto` центрирует его.

`.header`, `.logo`, `.auth-links` используют Flexbox. `display: flex` располагает дочерние элементы в строку; `align-items` выравнивает их поперёк строки; `justify-content: space-between` разносит логотип и навигацию к краям; `gap` задаёт расстояние между элементами. `padding-top`, `height` и `border-bottom` повторяют размеры и разделительную линию макета.

`.gallery-heading` тоже Flexbox: заголовок и кнопка находятся по разным краям. `h1` задаёт крупный размер и высоту строки и убирает браузерный `margin`, чтобы положение контролировалось макетом. `.add-button` располагает иконку с текстом рядом и задаёт высоту, отступы, округление и цвет.

### Галерея и карточка

`.cards` использует `display: grid`, чтобы сделать ровную сетку. `repeat(4, minmax(0, 1fr))` означает четыре колонки равной доли (`1fr`); `minmax(0, ...)` разрешает им сжиматься и не переполнять сетку. `gap` задаёт расстояние между карточками.

`.card` получает `position: relative`, чтобы дата и градиент могли позиционироваться внутри неё; `aspect-ratio: 1` делает форму квадратной; `overflow: hidden` обрезает выступающие части фото; `border-radius` скругляет углы; `background` служит цветом-заполнителем при загрузке.

`.card > img` выбирает только прямую картинку карточки. `width`/`height: 100%` заполняют квадрат, `object-fit: cover` масштабирует фотографию без растяжения и обрезает лишнее. `display: block` убирает небольшой зазор снизу, который обычно есть у строчных изображений.

`.card::after` — декоративный псевдоэлемент, которого нет в HTML. `content: ""` включает его отображение. Абсолютное позиционирование и `left/right/bottom: 0` растягивают его вдоль нижнего края карточки. `linear-gradient()` плавно затемняет фотографию под датой. Дата получает собственное абсолютное положение и `z-index: 1`, поэтому остаётся поверх градиента. На телефоне показываются часы `.clock`, а слова «Добавлено» скрываются.

### Подвал и диалог

`.footer` использует Flexbox, чтобы поставить email и информацию о разработчике по краям. `border-top` отделяет его линией, `padding` задаёт внутренние отступы.

`.modal` задаёт размер нативного `<dialog>`, ограничивает его ширину на узком экране, убирает стандартную рамку и скругляет углы. `margin: auto` помогает браузеру центрировать диалог. `::backdrop` — псевдоэлемент затемнения за открытым диалогом. У `.modal-content` максимальная высота ограничена размером окна браузера, `overflow-y: auto` добавляет внутреннюю прокрутку, если содержимое не помещается.

`.close-button` имеет `position: absolute` для расположения крестика в правом верхнем углу окна. `form-switch` центрирует переключатели. Состояние выбранной кнопки получает класс `active`, который добавляет JS, а CSS меняет её цвет.

### Сетка формы и состояния

`form` — CSS Grid из двух одинаковых колонок. В селекторе `#register-form .field:first-child` выбрано первое поле регистрации (имя), а `.consent-field`, `.submit-button`, `.form-hint` и `.form-status` занимают всю ширину через `grid-column: 1 / -1`.

`.field input` задаёт полям ширину и высоту, внутренние отступы, границу, фон и скругление. `outline: none` снимает стандартный контур, потому что отдельное правило `:focus` показывает выбранное поле синей границей. Псевдокласс `::placeholder` задаёт цвет подсказки. Селектор `[aria-invalid="true"]` окрашивает поле с ошибкой в красный, а `.error` оформляет текст под ним.

`.error:empty` скрывает пустое сообщение. `.consent-label` выравнивает флажок и текст; `flex-shrink: 0` не позволяет флажку сжаться. `accent-color` меняет его системный цвет.

`.submit-button:disabled` оформляет кнопку, заблокированную до согласия. Это только внешний вид; реальное свойство `disabled` присутствует в HTML и проверяется браузером. `.form-status:empty` скрывает статус до появления сообщения. `.visually-hidden` визуально обрезает подпись почти до нуля, но оставляет её доступной скринридеру.

### Адаптация под планшет и телефон

`@media (max-width: 1023px)` применяет вложенные правила при ширине экрана не более 1023 пикселей: заголовок становится меньше, а сетка переходит с четырёх колонок на три. `nth-child()` выбирает карточки по их позиции, чтобы сохранить порядок, заданный планшетным макетом.

`@media (max-width: 600px)` задаёт мобильные изменения: боковые поля становятся уже, текст у логотипа и кнопки добавления скрывается, карточки переходят на две колонки, дата показывает часы, подвал становится вертикальным, диалог и его отступы уменьшаются. Форма превращается в один столбец. Это один адаптивный документ; отдельные версии HTML для каждого устройства не нужны.

## 4. Разбор JavaScript

### Поиск элементов

`document.querySelector('#auth-modal')` находит первый элемент с таким `id`. `querySelector()` принимает CSS-селектор: `#` означает id, точка — класс, квадратные скобки — атрибут. `querySelectorAll()` возвращает все совпадения. Ссылки на элементы сохраняются в переменных `modal`, `registerForm`, `loginForm`, `consent` и `registerButton`, чтобы не искать их повторно.

`registerForm.elements.consent` обращается к контролу формы по его атрибуту `name="consent"`. `registerForm.querySelector('[type="submit"]')` ищет кнопку отправки внутри регистрации, а не на всей странице.

### Переключение форм

`switchForm(formName)` получает текстовое значение `register` или `login`. Сравнение `!==` выставляет `hidden` у невыбранной формы. Далее функция проходит по кнопкам `[data-switch-form]`: сравнивает их `dataset.switchForm` с текущей формой, добавляет или удаляет класс `active`, записывает состояние в `aria-pressed`. В конце она находит первое поле активной формы и вызывает `.focus()`, чтобы клавиатурный ввод сразу был направлен туда.

### События модального окна

`addEventListener('click', ...)` запускает функцию при клике. Кнопка открытия вызывает `modal.showModal()`, задаёт `overflow: hidden` для страницы позади окна и вызывает `switchForm()` с записанным в `data-open-form` значением. Кнопки внутри окна вызывают только `switchForm()`.

Кнопка закрытия вызывает `modal.close()`. Обработчик `click` самого `<dialog>` проверяет `event.target === modal`: это значит, что кликнули именно по области затемнения, а не по дочернему элементу формы. Событие `close` восстанавливает прокрутку. Escape поддерживает сам нативный `<dialog>`.

### Проверка согласия и ошибки

Событие `change` у checkbox возникает при отметке или снятии галочки. `consent.checked` — логическое значение. Выражение `!consent.checked` меняет его на противоположное, поэтому кнопка регистрации отключена без галочки и доступна с ней.

`showError(input, message)` получает поле и текст. `getAttribute('aria-describedby')` читает id связанного блока ошибки, `getElementById()` находит блок, а `textContent` меняет его текст безопасным способом — строка не интерпретируется как HTML. `setAttribute('aria-invalid', ...)` указывает, ошибочно ли поле.

### `validateForm(form)`

Функция проверяет только поля той формы, которую ей передали. `querySelectorAll('input')` находит поля, `forEach()` проходит по ним. `setCustomValidity('')` сначала очищает пользовательскую ошибку, затем создаётся переменная `message`.

`input.validity.valueMissing` означает, что обязательное поле пусто. `input.validity.typeMismatch` означает, что значение не соответствует типу, например email. Для регистрации выполняются дополнительные проверки:

- регулярное выражение имени начинается с `^` и заканчивается `$`, поэтому проверяется вся строка; первый символ должен быть русской буквой, после него разрешены русские буквы, пробел и дефис;
- `replace(/[\s()\-]/g, '')` удаляет из временной копии номера пробелы, скобки и дефисы (`g` — все совпадения). Само поле не переписывается;
- шаблон номера разрешает начало `+7`, `7` или `8`, потом цифру `9` и ещё девять цифр (`\d{9}`);
- пароль должен иметь длину не меньше шести (`length < 6`) и не состоять только из цифр (`/^\d+$/`);
- повторный пароль сравнивается с `form.elements.password.value`.

После проверок `setCustomValidity(message)` сохраняет ошибку в браузере, `showError()` показывает её, а `checkValidity()` определяет, правильно ли поле. Переменная `firstInvalidInput` запоминает первое неверное поле. В конце фокус переходит к нему и функция возвращает `false`; если ошибок нет, она возвращает `true`.

### Отправка форм

Массив `[registerForm, loginForm]` позволяет добавить одинаковые обработчики обеим формам. `input` срабатывает во время редактирования: обработчик очищает сообщение старой ошибки и общий статус.

`submit` возникает при отправке формы. `event.preventDefault()` отменяет стандартную перезагрузку/переход, потому что в этой работе нет серверной части. Сначала очищается статус, затем запускается `validateForm()`. `return` прекращает обработчик, если есть ошибки.

`new FormData(form)` собирает поля, у которых есть `name`. `Object.fromEntries()` превращает пары имени и значения в обычный объект, удобный для просмотра. Checkbox в `FormData` по умолчанию даёт строку `on`, поэтому для регистрации поле `consent` заменяется на `consent.checked` — `true` или `false`. `console.log()` печатает данные в Console разработчика, а `textContent` сообщает пользователю, что отправка обработана.

## 5. Что важно помнить при объяснении проекта

- HTML отвечает за смысл и структуру, CSS — за оформление и расположение, JavaScript — за реакцию на действия пользователя.
- `class` — общий крючок для оформления множества элементов; `id` — уникальное имя для связи с подписью или поиска одного элемента скриптом; `data-*` хранит собственное значение для JavaScript.
- `type="button"` и `type="submit"` различаются поведением. Первое не отправляет форму, второе запускает её проверку и событие `submit`.
- Атрибуты `required`, `type="email"`, `minlength` помогают проверке браузера, а `novalidate` позволяет показывать собственные сообщения вместо всплывающих подсказок.
- Медиазапросы меняют CSS для ширины экрана. HTML остаётся один и тот же.
- Форма здесь демонстрирует интерфейсную проверку и сбор данных. Она не хранит пароли, не создаёт аккаунт и не авторизует пользователя на сервере.

# Лабораторная работа № 1 — сервис скриншотов

Учебный проект по дисциплине «Технологии разработки WEB-приложений», вариант 4. Страница показывает статичные карточки скриншотов, адаптируется к разной ширине экрана и содержит формы регистрации и входа.

## Запуск

Откройте папку `Лабораторная работа 1` в редакторе кода и запустите `index.html` через расширение Live Server в VS Code. Также можно открыть терминал в этой папке и выполнить:

```text
py -m http.server 8000
```

После этого откройте [http://localhost:8000](http://localhost:8000). Страница использует обычные HTML, CSS и JavaScript: устанавливать библиотеки или собирать проект не нужно.

Для просмотра результата отправки формы откройте инструменты разработчика браузера клавишей `F12` и выберите вкладку **Console**. Форма демонстрационная: после проверки данные выводятся в консоль, серверной регистрации и входа нет.

## Как устроен HTML

В `index.html` задаются элементы и их смысл. В `<head>` указаны кодировка русскоязычной страницы, настройка ширины для мобильных экранов, заголовок вкладки, подключение CSS и JavaScript. Атрибут `defer` запускает скрипт после разбора HTML, поэтому JavaScript находит уже созданные элементы страницы.

В `<header>` находятся логотип и кнопки «Регистрация» и «Вход». Кнопки не отправляют форму: атрибуты `data-open-form` сообщают JavaScript, какое окно открыть. В `<main>` находятся заголовок месяца, неактивная кнопка добавления и галерея. Каждая карточка — отдельный `<article>` с изображением и датой внутри `<time>`. Эти семантические элементы помогают браузеру и вспомогательным технологиям понимать назначение содержимого.

Карточки написаны прямо в HTML, потому что в этой лабораторной они статичные. Для каждой картинки указан `alt` — короткое описание на случай, если изображение не загрузится или страницу читает скринридер. Кнопки добавления и загрузки пока отключены: их реальная работа не требуется для этой страницы.

В `<footer>` размещена контактная информация. Формы находятся в HTML-элементе `<dialog>`: браузер показывает его поверх страницы и затемняет фон. Внутри диалога две отдельные `<form>` — регистрация и вход. У каждой формы свои поля и кнопка отправки. `name` у поля задаёт имя значения при сборе данных, `required` помечает обязательные поля, а `type="email"` включает базовую проверку формата адреса.

`label` связывает подпись с полем ввода. Подписи скрыты только визуально классом `visually-hidden`, поэтому они доступны скринридеру. Элемент `<small>` под полем предназначен для сообщения об ошибке, а `aria-describedby` связывает сообщение с нужным полем. Атрибут `hidden` изначально скрывает форму входа, пока пользователь не выберет её.

## Как устроен CSS

В `css/style.css` описаны цвета, шрифт, размеры, расположение элементов и состояния кнопок. В начале через `@font-face` подключены локальные начертания Inter. Правило `box-sizing: border-box` упрощает расчёт размеров: ширина элемента включает его внутренние отступы и границы.

Класс `.container` задаёт общую ширину и боковые поля шапки, основного содержимого и подвала. `.cards` использует CSS Grid: на широком экране карточки размещаются в четыре колонки, а одинаковые доли колонок сохраняют их равную ширину. `.card` задаёт квадратную область с обрезкой по краям, а `object-fit: cover` заполняет её изображением без искажения пропорций. Затемнение у нижнего края карточки сделано псевдоэлементом `::after`, чтобы дата читалась поверх фотографии.

Стили `.modal`, `.modal-content`, `.form-switch` и `.field` оформляют диалог и поля. Селекторы `:hover`, `:focus`, `[aria-invalid="true"]` и `:disabled` задают вид при наведении, вводе с клавиатуры, ошибке и недоступности кнопки. Пустые блоки ошибок и состояния скрываются через `:empty`, поэтому под полями не остаётся лишнего места.

Внизу файла находятся медиазапросы `@media`. При ширине до 1023 пикселей сетка меняется на три колонки. При ширине до 600 пикселей остаются две колонки, скрывается текст рядом с логотипом, а поля форм выстраиваются в один столбец. Медиазапросы позволяют использовать одну HTML-страницу на телефоне, планшете и компьютере и менять только те стили, которые зависят от ширины.

## Как устроен JavaScript

В `js/script.js` сначала через `querySelector()` находятся диалог, формы, галочка согласия и кнопка регистрации. Переменные нужны, чтобы обращаться к одним и тем же элементам в нескольких обработчиках.

Функция `switchForm()` показывает выбранную форму и скрывает другую. Обработчики `click` на кнопках с `data-open-form` открывают диалог и переключают его на нужную форму. Кнопки внутри диалога переключают регистрацию и вход. Крестик и клик по затемнённой области закрывают диалог; клавишу Escape обрабатывает сам `<dialog>`. После закрытия возвращается прокрутка страницы.

Обработчик `change` на галочке согласия включает кнопку регистрации только тогда, когда галочка отмечена. Функция `showError()` помещает текст ошибки под нужным полем и обновляет `aria-invalid`, чтобы состояние было понятно не только визуально.

Функция `validateForm()` проходит по полям перед отправкой. Она использует встроенные свойства браузера для проверки обязательности поля и формата email. Для регистрации добавлены условия задания: имя русскими буквами, российский мобильный номер, пароль от шести символов и совпадение повторного пароля. Номер можно ввести цифрами, например `79205235127`, или с `+7`/`8`, пробелами и дефисами. Проверка очищает только копию строки, поэтому исходное значение в поле не меняется.

Обработчик `input` убирает старую ошибку, когда пользователь снова редактирует поле. Обработчик `submit` вызывает `preventDefault()`, чтобы браузер не перезагружал страницу и не отправлял данные на сервер. Если проверка успешна, `FormData` собирает значения формы, после чего `console.log()` выводит их в консоль. Значение согласия преобразуется в `true` или `false`.

## Изображения и материалы

Изображения, значки и логотип лежат в `assets/images/`, чтобы HTML ссылался на файлы по понятным именам. Шрифт и лицензия находятся в `assets/fonts/`. Исходный макет страницы — [Figma из задания](https://www.figma.com/file/RX3kyfRxj3l8XRm4Kjqe5G/?node-id=0%3A1); используемая копия — [Figma пользователя](https://www.figma.com/design/iPemIJcoyLsmi3iekNM9t9/).

Кнопки «Добавить скриншот» и «Показать ещё» имеют только визуальные состояния: первая меняется при нажатии (`:active`), вторая подсвечивается при наведении (`:hover`). Курсор показывает, что это кнопки. Загрузка файлов, подгрузка карточек, хранение скриншотов и настоящая регистрация не реализованы.
